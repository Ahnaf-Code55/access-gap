# Demo walkthrough

Target: a public video under three minutes, once live AI and hosting are tested.

1. **Problem (20 seconds):** accessibility information can be incomplete or contradictory. Access Gap builds a checklist from supplied evidence without converting missing facts into a confident verdict.
2. **Sample (30 seconds):** show the fictional example. Open the two pavement sources, show their disagreement, then show the clinic's old toilet report remaining unknown.
3. **Your journey (50 seconds):** start a new journey, enter two fictional QA places, and add a dated venue excerpt about its entrance. Show the reported fact. Add an opposing account; show the conflict and generated follow-up question.
4. **AI (40 seconds, only once tested):** explain the sharing consent, select it, request questions from Nemotron on Nebius, and show the selected fixed-template questions and their check numbers alongside the unchanged evidence cards. Explain that AI selects checks and cannot verify or rewrite evidence. Do not present a mock response as a live call.
5. **Takeaway (20 seconds):** check an item and download the checklist. Explain that sources and unknowns are preserved for the user's own confirmation.

## Remaining release items

- Independent review of the integrated evidence workflow and security patch. Local abuse controls are implemented; public authentication, provider monetary controls and hosting/proxy review remain.
- Separately authorize a small fictional-data call with a dedicated capped Nebius key and available NVIDIA model. Verify the restricted JSON ID-selection contract, fixed question templates and failure handling; offline mocks establish no live compatibility.
- Demonstrate fictional fixtures and fictional QA entries until privacy/data-source approval. Any later real examples require permission, attribution and the privacy/release gates.
- Test with wheelchair users or accessibility practitioners; get feedback and avoid overstating completeness.
- Complete the security/privacy release checklist before hosting a protected free-to-test demo, recording the video, completing tool feedback and submitting to Devpost.

The project is currently local and the live model has not been exercised. The example is a transparent demonstration fixture, not real-world evidence.

Downloaded reports include source links, excerpts and checkbox state and remain wherever saved/shared. Use fictional QA data and explain this persistence during the download step. See [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) for release gates.
